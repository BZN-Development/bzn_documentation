---
title: "Troubleshooting"
---

Find the message from your server console below. Turn on more detail with
`setr bzn:debug 1`, and check every module with `bzn modules`.

## Startup [#startup]

### `bzn_config not found, using defaults for everything` [#bzn_config-not-found-using-defaults-for-everything]

`bzn_config` is missing or starts after bzn_core. Copy `bzn_core/templates/bzn_config` to
your resources and `ensure bzn_config` **before** `ensure bzn_core`.

### `core migrations failed; bzn_core will not start` [#core-migrations-failed-bzn_core-will-not-start]

A database step failed. The line above it says which one and why:

```
[bzn:db] core migration step 4 failed, staying at version 3: <error>
```

Common causes: the database user lacks `CREATE`/`ALTER` rights, or the database is too old
(MySQL 8+ or MariaDB 10.5+ are required). Fix it and restart; bzn continues from the step
that failed.

### `<module> not started: dependency "<name>" is not running` [#not-started-dependency-is-not-running]

A module needs another module that is turned off or failed. `bzn modules` shows the status
of each. Turn the dependency back on (`enabled = true`) or turn this module off too.

### `unknown option <section>.<option> in <file> (typo?)` [#unknown-option-in-typo]

A config file sets an option that does not exist, usually a typo or an option in the wrong
section. Compare with [Configuration](/docs/config); the option is ignored until fixed.

### `syntax error in shared/<section>.lua` [#syntax-error-in-shared-lua]

A Lua error in one of your `bzn_config` files. The message has the line. The whole file is
ignored until it is fixed.

### `roles cannot be applied: bzn_core may not change principals` [#roles-cannot-be-applied-bzn_core-may-not-change-principals]

### `ACE principals are off: bzn_core may not change principals` [#ace-principals-are-off-bzn_core-may-not-change-principals]

Add to your server config and restart:

```ini
add_ace resource.bzn_core command.add_principal allow
add_ace resource.bzn_core command.remove_principal allow
```

### `sv_stateBagStrictMode is off` / `sv_protectServerEntities is off` [#sv_statebagstrictmode-is-off-sv_protectserverentities-is-off]

A server setting bzn relies on for security is off. The message has the line to add to
`server.cfg`. Restart the **whole server** afterwards: `restart bzn_core` is not enough for
these.

```ini
setr sv_stateBagStrictMode true
set sv_protectServerEntities true
```

### `strictBoot: ... must be on; bzn_core will not start` [#strictboot-must-be-on-bzn_core-will-not-start]

The same, with `core.strictBoot = true`: core refuses to start until the settings are on.

### `<adapter> provider <name> is missing <function>` [#provider-is-missing]

A [provider](/docs/adapters) does not have a function core relies on. With the providers bzn
ships this means a file is missing or old: update bzn_core as a whole.

### `<module>: skipped: not for <game>` [#skipped-not-for]

The module is for another game (its `games` list). Nothing is wrong.

### `slow query (<n> ms): ...` [#slow-query-ms]

A database call took `db.slowQueryMs` (150 ms) or longer. One now and then during a
restart is normal. The same query again and again means a missing index or a database
under pressure.

### `ox_inventory bridge: ... Copy bzn_core/bridges/ox_inventory/ to ...` [#ox_inventory-bridge-copy-bzn_core-bridges-ox_inventory-to]

The ox_inventory bridge is missing or older than the one in bzn_core (usually after an
ox_inventory update). Copy the folder again as the message says. See
[Inventory](/docs/inventory).

### `ox_inventory is installed but inventory:framework is "..."` [#ox_inventory-is-installed-but-inventory-framework-is]

Set `setr inventory:framework "bzn"`.

## Joining [#joining]

### "This server requires ..." [#this-server-requires]

The player is missing an identifier in `players.requiredIdentifiers`, for example Discord
not running. The message tells them what to do.

### "This account is already connected to the server." [#this-account-is-already-connected-to-the-server]

The same Rockstar license is already online, and that connection is still alive. Allow two
at once with `players.duplicateLicense = true` (not recommended on a live server).

After a crash the old connection stays on the server until it times out. When the same
license connects again and the old connection has been silent for
`players.replaceDeadAfter` seconds (15), bzn drops the old one, saves its character and lets
the new one in. A player who reconnects faster than that sees this message once: trying
again a few seconds later works.

### "You are banned from this server." [#you-are-banned-from-this-server]

The user, an identifier they share with a banned user, or two of their hardware tokens
match a ban. `bzn bans <target>` shows it; `bzn unban <ban id>` lifts it. See
[Bans](/docs/bans).

### "The server is restarting. Please connect again in a moment." [#the-server-is-restarting-please-connect-again-in-a-moment]

A scheduled txAdmin restart is 10 seconds away or less. Core has saved everything and
refuses new connections until the server is back.

### Stuck on the loading screen [#stuck-on-the-loading-screen]

- A resource called `characters.useSelector()` but never calls `characters.select`. Stop
  it, or fix it; selection becomes automatic when it stops.
- `<name> has no characters and no selector is running`: the user has no characters and
  `characters.devCharacter` is off. Install a character selection resource or turn it on.

## In game [#in-game]

### `you are not allowed to use this command` [#you-are-not-allowed-to-use-this-command]

The player has no staff role. Give them one from the server console:

```
bzn role set <server id> admin
```

### `needs the role <role> or higher` [#needs-the-role-or-higher]

The player has a role, but the subcommand needs a higher one. The table is in
[Commands](/docs/commands#who-can-run-what).

### `you can only change roles below your own` [#you-can-only-change-roles-below-your-own]

Nobody can give a role at or above their own in game, and that includes changing their own.
Do it from the server console.

### Spawned at the airport [#spawned-at-the-airport]

The default spawn is used when:

- the character is new;
- its saved position was unusable (`saved position of character ... is not usable`):
  near `0, 0, 0` after a crash on join;
- the client found no ground at all (`no ground at ...`).

A position under the map is not a reason: the client moves the player up to the ground.
See [Spawning](/docs/spawn#crash-safety).

### Inventory empty or not loading [#inventory-empty-or-not-loading]

ox_inventory must start **after** bzn_core, and the bridge must be installed with
`inventory:framework "bzn"`.

### Salary not paid [#salary-not-paid]

- Is the character on duty? `bzn groups player <id>`.
- Does the grade have a salary? `bzn groups info <group>`.
- Is the group paid by its own account and out of money? `bzn payroll debts <group>` shows
  what it owes; it is paid as soon as the account has money.

### Food does nothing [#food-does-nothing]

The item needs `server = { status = { hunger = 20 } }` in ox_inventory's `items.lua`.
ox_inventory's own `client.status` is not used. See [Status](/docs/modules/status#food-and-drink).

### A vehicle drops or sinks when it spawns [#a-vehicle-drops-or-sinks-when-it-spawns]

bzn spawns vehicles at the ground height a nearby client reports. With no player within
300 m, the given height is used: give garage spawn points at ground level.

### "refused opening trunk...: plate ... was shown by 2 vehicle(s)" [#refused-opening-trunk-plate-was-shown-by-2-vehicle-s]

Another script gave a vehicle a plate an owned vehicle has. bzn gave that vehicle a new plate
and refused the one open; opening again shows the right trunk. Nothing leaked.

### A player cannot lock their own car [#a-player-cannot-lock-their-own-car]

- `keyMode = 'item'`: the owner needs a key item too (`bzn vehicles keyitem <vehicle> <id>`).
- After `changelocks`, old keys no longer work.
- A group vehicle needs the grade permission `vehicle.use`.

## Getting help [#getting-help]

When you ask for help, include:

- the console output from start to the problem, with `setr bzn:debug 1`;
- the output of `bzn modules`;
- your bzn_core version (top of `fxmanifest.lua`) and artifact version.
