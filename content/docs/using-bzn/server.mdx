---
title: "Server side"
---

The server is where bzn's data lives and where every decision is made. Your server code
asks bzn for data, changes it through the API, and reacts to hooks.

## Who is this player? [#who-is-this-player]

Almost everything starts with turning a server id into a character:

```lua
RegisterNetEvent('myjob:startShift', function()
    local src = source
    local character = bzn.characters.get(src)
    if not character then return end   -- still in character selection

    print(character.id, character.firstName, character.lastName)
end)
```

| You have | You want | Call |
| --- | --- | --- |
| server id | the loaded character | `bzn.characters.get(src)` |
| character id | the server id (if online) | `bzn.characters.getSource(charId)` |
| server id | the user (person) | `bzn.players.get(src).userId` |
| user id | the online player | `bzn.players.getByUserId(userId)` |

## Reading data [#reading-data]

```lua
local charId = bzn.characters.get(src).id

-- groups
bzn.groups.getMemberships(charId)                  -- { police = 2 }
bzn.groups.hasPermission(charId, 'police', 'armory')
bzn.groups.getDuty(charId)                         -- 'police' or nil
bzn.groups.countOnDuty('police')

-- money
local personal = bzn.accounts.getPersonal(charId)
bzn.accounts.balance(personal.id)
bzn.accounts.cash(src)

-- statuses
bzn.status.get(charId, 'hunger')

-- staff
bzn.roles.has(src, 'admin')
```

Group and account functions also work for offline characters (they read the database).
Statuses only exist for loaded characters.

## Changing data [#changing-data]

Change things through the API, never by writing to bzn's tables yourself: the API keeps
the cache, the clients, the hooks and the statements in step.

```lua
-- pay for something: cash if they have enough, else the bank
local ok, method = bzn.accounts.pay(src, 250, { type = 'purchase', reason = 'Repair kit' })
if not ok then
    return TriggerClientEvent('ox_lib:notify', src, { type = 'error', description = 'Not enough money' })
end

-- hire someone
local ok, err = bzn.groups.add(charId, 'mechanic', 0)

-- give a reward
bzn.accounts.credit(personal.id, 1000, { type = 'reward', reason = 'Delivery done' })

-- make them thirsty faster while they work
bzn.status.setModifier(charId, 'thirst', 'myjob:working', -1.0)
```

### When a player asks for something [#when-a-player-asks-for-something]

Never trust what a client sends. Take the player from `source`, check the permission
on the server, and let bzn check money and limits:

```lua
RegisterNetEvent('mybank:withdraw', function(accountId, amount)
    local src = source
    local character = bzn.characters.get(src)
    if not character then return end

    -- bzn checks that this player's character may withdraw from this account,
    -- that the amount is a valid whole number, and that the money is there
    local ok, err = bzn.accounts.withdrawCash(src, accountId, amount)
    TriggerClientEvent('mybank:result', src, ok, err)
end)
```

Functions that act for a player take `charId` (in `info` or `opts`) and check permissions
themselves. Without it, the call is trusted: use that only for your own logic, never with
values straight from a client.

## Reacting to events [#reacting-to-events]

Use hooks instead of loops:

```lua
-- load your data with the character
bzn.hooks.on('character:loaded', function(src, character)
    myData[character.id] = loadFromDb(character.id)
end)

-- clean up when they leave (logout, disconnect, shutdown)
bzn.hooks.on('character:unloading', function(src, character, reason)
    saveToDb(character.id, myData[character.id])
    myData[character.id] = nil
end)

-- on duty / off duty
bzn.hooks.on('groups:dutyChanged', function(charId, group, previous, src)
    if group == 'police' then giveRadio(src) end
end)

-- add a rule: only five mechanics on duty at once
bzn.hooks.on('groups:beforeDuty', function(charId, group)
    if group == 'mechanic' and bzn.groups.countOnDuty('mechanic') >= 5 then
        return false, 'too_many_mechanics'
    end
end)
```

## Sending data to the client [#sending-data-to-the-client]

bzn already sends each player its own groups, accounts and statuses. For your own data,
send it to that one player, when it changes:

```lua
TriggerClientEvent('myjob:shiftStarted', src, { route = route, pay = 500 })
```

Do not put private data in state bags or `GlobalState`: every client can read those.

For data the client asks for (open a menu), use an ox_lib callback:

```lua
lib.callback.register('myshop:getStock', function(src)
    if not bzn.characters.get(src) then return nil end
    return stock
end)
```

## Your own tables [#your-own-tables]

Create tables with bzn's migrations, so they are made once and upgraded safely:

```lua
bzn.onReady(function()
    bzn.db.migrate({
        [[CREATE TABLE IF NOT EXISTS `myjob_routes` (...)]],
    })
end)
```

See [Saving and the database](/docs/database).

## Checklist [#checklist]

- Get the character from `source`, never from an id the client sent.
- Store your data by character id.
- Change money, groups and statuses through the API.
- Pass `charId` when a player acts, so bzn checks the permission.
- React with hooks; no `while true` loops checking state.
