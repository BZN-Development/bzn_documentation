## `spawn:spawning` [#spawn-spawning]

`(point)` The character is about to be placed at `point` (before the teleport). Used to move
a camera there; see `spawn.setTransition` in [Spawning](/docs/spawn).

```lua
-- point your selection camera at where the character will appear
bzn.hooks.on('spawn:spawning', function(point)
    SetCamCoord(cam, point.x, point.y, point.z + 40.0)
    PointCamAtCoord(cam, point.x, point.y, point.z)
end)
```

## `spawn:pedReady` [#spawn-pedready]

`(ped, point)` The ped has its final model and is in place, but the screen is still dark (or
a transition camera shows something else). Dress the ped here, so the default clothes are
never seen. Do not wait inside the handler: the spawn goes on right after it.

```lua
-- an appearance resource dresses the ped before anyone sees it
bzn.hooks.on('spawn:pedReady', function(ped, point)
    applyOutfit(ped, savedOutfit)   -- do not Wait() in here
end)
```

## `spawn:spawned` [#spawn-spawned]

`(point)` The player spawned and the screen faded in.

```lua
bzn.hooks.on('spawn:spawned', function(point)
    DisplayRadar(true)
    SendNUIMessage({ action = 'showHud' })
end)
```

## `spawn:blocked` [#spawn-blocked]

`(reason)` A server hook (`spawn:beforeSpawn`) held the spawn back, for example
`'appearance_required'` while the character creator runs. A resource that took over the
picture (`spawn.setTransition`) should give it back now. The spawn comes later, with the
usual `spawn:spawning` and `spawn:spawned`.

```lua
bzn.hooks.on('spawn:blocked', function(reason)
    if reason == 'appearance_required' then
        destroySelectionCamera()   -- the creator shows its own picture now
    end
end)
```
